CSS live-state font probes v2

Zero JavaScript. Editable form state is transformed by OpenType shaping into deterministic geometry; CSS copies that geometry with anchor-size() and classifies it using container queries.

1 — Metric probe: live character count

Every printable ASCII glyph has exactly a 1em advance. Change the text; the meter classifies the live intrinsic width.

2 — Token probe: text → number

GSUB ligatures collapse known strings to synthetic glyphs whose hmtx advances are 8/12/16/20em. Try ALICE, BOB, CAROL, or DAVE.

3 — Context probe: ordered bounded string → number

Contextual substitutions assign different advances by position. The mapping is injective for ^[ABC]{1,3}. In particular, order changes the result.

4 (legacy) — Scroll × font geometry

The fixed token ALICE shapes to 8em. Horizontal scroll progress drives its font size from 8px → 20px, so its live width computes 8 × scroll-scale. Snap through the four positions.

2b — Token ligature under calt instead of liga

Same font advances as #2, different OpenType feature. This isolates whether editable controls suppress normal ligatures near the caret.

5 — Variable font addressing (manual, no scrolling)

A single input stores ^ABC. The variable-font ADDR axis instructs OpenType to zero out every positional glyph except the addressed one. Expected widths: 5em (A), 9em (B), 13em (C).

6 — Isolated scroll → font axis → glyph width

Scroll this strip between its four snap positions. First inspect the progress bar, then the font measurements. Both inputs are outside the scroller, so their width cannot alter its scroll range.
